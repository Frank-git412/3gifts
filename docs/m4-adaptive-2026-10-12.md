# M4 Adaptive query ordering

Query strategy `20261012-m4-adaptive`. Ranking remains `20261010-m4-notes` because product filters, weights and ranking comparisons are unchanged. The public response exposes the query strategy separately.

The existing plan still supplies at most twelve queries. After each catalogue response, the next query first addresses an interest absent from the selected set, then a missing requested subcategory when three cards can represent all requested subcategories. Ties retain the existing plan order.

Within the same coverage need, generic searches from a family whose last generic query did not change the selected products are deferred behind other candidates. They are not deleted and remain reachable if the search is still incomplete. A subsequent successful generic observation resets this deferral. Targeted note, required-property and contextual queries are not penalized. Failure of an occasion-specific or otherwise targeted query does not demote the broader base query.

The evidence is local to one request. There is no persistent success model, cross-visitor profiling or fabricated historical ranking of families. The original questionnaire, UI, shared daily allowance, catalogue pacing, cache duration, early-child checks, mandatory-note checks, age-review fallback, product identity and early-stop coverage requirements remain in place.

Each executed query reports the reason for its priority, the areas/subcategories missing before execution and whether the selected set changed. These diagnostics contain normalized fields, not the visitor's raw note.

Fourteen adaptive tests include preservation of the exact bounded query set on all 120 frozen M3 profiles. A paired compiled-Worker fixture holds the catalogue, filters, ranking and inputs fixed, changing only the query scheduler to compare round-robin and adaptive order. In the missing-interest case: six versus five catalogue calls; identical three ASINs, order and ranking evidence. The repeat makes zero new catalogue calls; refinement excludes prior results. Its elapsed clock is simulated and is not a measured speedup on Amazon.

The 11 October timing sample is a separate historical baseline. A four-profile live check surrounds this release; a shared-cache repeat must not be presented as a causal time improvement.
