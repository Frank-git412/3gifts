# M4 — notes, coverage and operational diagnostics

Revision: `20261010-m4-notes`. This continues v126; M4 is not closed.

## Note contract

Ordinary recognized tastes are optional signals. Explicit `solo/only`, mandatory wording and requests such as `cerco/I want` remain filters. Supported optional note evidence contributes the existing 20-point channel; mandatory signals do not earn the same bonus. The denominator remains common to every candidate. Generic tastes use bounded listing recognizers; unsupported signals do not acquire invented evidence.

The reviewed M3 expressions distinguish preference clauses (`likes a novel about nature`) from specific requests. Optional expressions may prioritize an existing selected family, retaining its alternatives and the selected interests. They require actual title/feature evidence to score, including existing host checks where relevant. No optional note adds an unselected interest.

Known uncertainty patterns produce neither positive nor negative tastes. A restriction mixed into unresolved uncertainty blocks the request. Mandatory/excluded contradictions block it. Existing exclusions, ingredient/property and compatibility checks remain. This is a bounded local parser, not universal natural-language understanding or product certification.

Normalized note records expose type, value, scope, origin, language and status. The original note stays in the browser; request fields contain controlled signals. Two successive IT/EN refinements retain original constraints and distinguish newly introduced refinement records. This release does not introduce persistent visitor-note logging.

## Coverage and row accounting

Within the existing age tier, a one-card lookahead prevents selecting a parent variant or equivalent function that would consume the only distinct proposal for the other interest. Two interests remain the supported maximum. Existing age-documentation priority, event/category precedence and duplicate rejection remain.

Every received catalogue row gets a `diagnostics.normalization` decision keyed by query and row index, with ASIN when valid. Reasons cover invalid identity/title/URL, adult-only content, exclusions, missing eligible offer, invalid price and recipient mismatch. `no_eligible_offer` aggregates the current offer checks (EUR, stock, price range and MAP); it does not assert an unavailable listing is out of stock. Repeated observations keep separate row records and subsequently merge by ASIN. Final candidate decisions and scoring evidence remain separate. Response duration is now exposed in milliseconds.
